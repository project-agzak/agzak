#### (2) Nginx / HTTPS 구성 (요약)

* 설정 파일: `deploy/infra/nginx/data/nginx/*.conf`
* 인증서: Let’s Encrypt / Certbot

  * `/etc/letsencrypt/live/agzak.co.kr/fullchain.pem`
  * `/etc/letsencrypt/live/agzak.co.kr/privkey.pem`

핵심 서버 블록:

```nginx
server {
    listen 443 ssl;
    server_name agzak.co.kr www.agzak.co.kr;

    ssl_certificate     /etc/letsencrypt/live/agzak.co.kr/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/agzak.co.kr/privkey.pem;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://agzak-be-active:8082;  # blue/green active slot
    }
}

server {
    listen 80;
    server_name agzak.co.kr www.agzak.co.kr;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

## 2. 프로젝트에서 사용하는 외부 서비스 포팅 매뉴얼

### 2-1. Kakao 소셜 로그인

#### 1) 사용 목적

* 카카오 계정 기반 간편 로그인
* 게스트 운세 → 카카오 로그인 → 추가정보 입력 → 정회원 전환
* JWT Access/Refresh 발급 후 프론트에서 저장, API 호출 시 `Authorization: Bearer` 헤더 사용

#### 2) 서비스 정보

* 프로토콜: OAuth 2.0 (Authorization Code)
* 스코프: `profile_nickname`
* Kakao API 엔드포인트

  * Authorize: `https://kauth.kakao.com/oauth/authorize`
  * Token   : `https://kauth.kakao.com/oauth/token`
  * Me      : `https://kapi.kakao.com/v2/user/me`

#### 3) 백엔드 엔드포인트 개요

* 카카오 로그인 처리

  * Request Body: `KakaoLoginRequest`

    * `authCode`, `redirectUri`, `guestId(optional)`
  * Response: `SocialLoginResponse`

    * 기존 회원/신규 회원 여부, 추가정보 필요 여부 등 포함
* 추가정보 입력 완료

  * Request Body: `KakaoCompleteSignupRequest`
  * Response: `TokenResponse` (Access/Refresh 토큰)

> 실제 엔드포인트 URL 및 스키마는 `/api/swagger-ui.html` 의 Auth API 문서에서 확인 가능.

#### 4) 환경 변수 / 설정

* `KAKAO_REST_KEY`
* `KAKAO_JS_KEY`
* 프론트에서 `redirectUri` 를 `https://www.agzak.co.kr/...` 기반으로 전달
* Kakao Developers 콘솔에 **Redirect URI** 로 동일 도메인 등록 필요

### 2-3. GMS LLM (SSAFY OpenAI Proxy) + RAG

#### 1) 사용 목적

* 운세 점수 및 driver key 기반 자연어 운세 해설 생성
* SSAFY GMS 게이트웨이를 통해 OpenAI 호환 API 호출 (직접 키 노출 X)

#### 2) 서비스 정보

* GMS Base URL: `https://gms.ssafy.io/gmsapi/api.openai.com/v1`
* 기본 모델: `gpt-4.1-mini`
* 요청 타임아웃: 5초

#### 3) 환경 변수 / 설정

**Spring Boot**

```yaml
gms:
  enabled: true
  base-url: "https://gms.ssafy.io/gmsapi/api.openai.com/v1"
  api-key: ${GMS_API_KEY}
  timeout:
    ms: 5000
  model: ${GPT_MODEL:gpt-4.1-mini}
```

* `GMS_API_KEY`
* `GPT_MODEL` (선택)

**FastAPI (AI)**

* `GMS_API_KEY`
* `GMS_BASE_URL`
* `GMS_MODEL`

#### 4) 동작 개요

1. **RAG DB 빌더**

   * `ASTROLOGY_KEYS` 목록을 기준으로 GMS에 프롬프트 전송
   * 응답으로 받은 전문가 해설 텍스트를 MySQL `interpretations(aspect_key, category, interpretation_text)` 에 upsert
2. **운세 요약 API (`/summarize`)**

   * 입력: Java 운세 엔진이 계산한 `scores` + `keyDrivers`
   * 처리:

     * driver key 로 RAG DB 에서 해설 텍스트 조회
     * 각 영역별 해설을 LLM에 전달해 한 문장 요약 생성
     * 전체 총운 한 문장 요약 추가 생성
   * 출력: `FortuneScoreResponse`
     (`total_score`, love/money/health/achievement 점수, `total_summary`, `detailed_summaries`)

GMS 오류 시 기본 문구로 대체하는 예외 처리 로직이 있어, 장애 시에도 전체 서비스가 중단되지 않도록 설계되어 있다.
